Bifrost Northstar

The Bifrost Northstar is the set of engineering and operating axioms this project is built to. They are enforced mechanically, by hooks and gates and tests, never by memory or by prose. When a rule can be automated, it is automated. That is itself one of the rules.

  1. Zero Local Secrets

    Credentials are fetched from a vault at runtime, never committed and never hardcoded. The codebase holds no keys; bf and the system Keychain do. A secret that is written down is a secret already lost.

  2. Loud by default

    Every error path emits a structured log line. No empty catches, no swallowed errors, no silent return nil. A path that cannot be validated end to end is marked a known deficiency, never shipped as if it were clean.

  3. Honest measurement

    Numbers are published with their methodology, and raw inputs never quietly vanish. A claim that cannot be falsified is not a claim; it is marketing. The Council abhors marketing.

  4. Commodity Intelligence

    No hardcoded model id. Models are a commodity, and the pipeline treats them as such. The code stays provider-agnostic so a better model can replace a worse one without a rewrite.

  5. Mechanize, not md

    A recurring behavioral gap is not fixed by writing a document about it. It is baked into a hook, a script, a gate, or a test. Documentation records where the mechanism lives; it does not do the work.

  6. Defer nothing

    Unblocked work is executed now. Truly blocked work is filed to the task store this turn, never left as a footnote in prose. A "later" is a red flag, not a resolution.

  7. Age is not a gate

    Work is not stale because it is old. A thing is merged or closed on its merits, never because of the date on it, and never asked "do you still want this?" as a reason to discard it.

  8. Plan is consent

    A plan plus a green light authorizes the whole scope: the waves, the parallelism, the cost, the duration. Re-confirming is forbidden; firing is the expectation.

  9. File it, then fix it

    Any warning, deprecation, retirement, or end-of-life that surfaces becomes a task with a canonical replacement and a migration, not a note-and-move-on. The point is to stop re-encountering the same dead endpoint every session.

These axioms live as enforceable mechanisms across the projects that subscribe to them. For the project itself, see hydratype on GitHub. Read the wider project from the top: hydratype, Article IV.
